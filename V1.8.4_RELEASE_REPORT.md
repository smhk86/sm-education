# SM SCHOOL AI v1.8.4 — Release report

## Scope
Parent-only, explicitly initiated, one-time encrypted transfer of the local family backup to another device signed in to the same parent account. No student or teacher accounts were added.

## Security and privacy design
- The browser creates a 128-bit random transfer code and derives an AES-256-GCM key from it using PBKDF2-HMAC-SHA256 with 310,000 iterations and a random salt.
- The local backup is encrypted before upload. The API receives only ciphertext, the salt/IV envelope, and a SHA-256 fingerprint of the transfer code; it does not receive the transfer code or plaintext student data.
- The server scopes each package to the authenticated parent account, expires it after 20 minutes, and consumes it atomically on successful redemption.
- The receiving device must be signed in to the same parent account, decrypt the package locally, pass the existing local-backup validator, and receive explicit confirmation before replacing included local records.
- The transfer code must be treated as a secret. Anyone with the code and an authenticated session for that parent account could attempt redemption.

## Limitations
- This is a one-time encrypted backup transfer, not automatic, continuous, or bidirectional synchronization. Repeat the process to transfer an updated snapshot.
- HTTPS/Web Crypto is required. Email verification, password recovery, MFA, and production-grade login rate limiting remain outside this release.
- Existing backup schema limits apply; the encrypted envelope is capped at 8 MB by the API.
- APK build and production deployment were not performed.

## Compatibility
Existing learning APIs, curriculum data, AI tutor routes, local progress schema, and parent authentication behavior are retained. No student/teacher roles or public student-data endpoints are introduced.
