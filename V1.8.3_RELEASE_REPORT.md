# SM SCHOOL AI v1.8.3 — Parent-only accounts

## Scope
This release implements the user's requested parent-only account direction. It does not create student or teacher accounts.

## Backend
- `POST /api/v1/parents/register`: create a parent account.
- `POST /api/v1/parents/login`: authenticate a parent.
- `GET /api/v1/parents/me`: retrieve the authenticated parent identity.
- `POST /api/v1/parents/logout`: revoke the current session.
- `PUT /api/v1/parents/password`: change password and revoke all active sessions.
- SQLite role constraint permits only `parent` accounts. Passwords use PBKDF2-HMAC-SHA256 with 310,000 rounds and random salts. Random bearer tokens are stored as SHA-256 hashes and expire after 30 days.

## Frontend
- Parent Portal has registration, sign-in, sign-out and password-change controls in Arabic, French and English.
- Local family dashboard and family planner are displayed only after a valid parent session is restored or established.
- Learner records remain stored locally on the device. This version does not synchronize learner data to the parent account or across devices.

## Security and deployment limits
- HTTPS is required for production.
- Set `PARENT_AUTH_DB` to a persistent private volume; do not place the database in a public/static web directory.
- Email ownership verification, password-reset delivery, multi-factor authentication and production rate-limiting are not included yet. Do not treat this as a fully production-hardened identity service until those controls are added.
- Keep database backups private and access-controlled.

## Validation
